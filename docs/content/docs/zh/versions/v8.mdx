---
title: 升级到 v8
description: Orval v8 迁移指南
---

v8 带来了多项重要改进，重点聚焦于现代 JavaScript 生态支持，以及更完善的 Zod schema 集成。

## 新功能

### ESM（ECMAScript Modules）

整个项目都已从 CommonJS 迁移到 ESM。

**关键变化：**
- 所有 package 都在 `package.json` 中使用 `"type": "module"`
- 使用 `import`/`export` 语法，而不是 `require()`
- **要求 Node.js 22.18 或更高版本**

```bash
# 将配置文件重命名为 .mjs
mv orval.config.js orval.config.mjs

# 或者在 package.json 中添加
# "type": "module"
```

### 默认 HTTP Client：Fetch

默认 HTTP client 已从 `axios` 改为 `fetch`，以获得更小的 bundle 体积。

如果你想继续使用 axios：

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      httpClient: 'axios',
      target: './src/api',
    },
  },
});
```

### 新框架支持

**Angular Query：**

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      client: 'angular-query',
      target: './src/api',
    },
  },
});
```

**Solid Query / SolidStart：**

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      client: 'solid-query',
      target: './src/api',
    },
  },
});
```

### 增强的 Zod 集成

**Schema 类型选择：**

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      schemas: {
        path: './model',
        type: 'zod', // 'typescript' | 'zod'
      },
    },
  },
});
```

**运行时校验：**

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      schemas: { type: 'zod' },
      client: 'fetch',
      override: {
        fetch: {
          runtimeValidation: { strategy: 'both' },
        },
      },
    },
  },
});
```

`runtimeValidation: true` 仍然受支持，它是 `{ strategy: 'throw' }` 的简写形式。

### React Compiler 支持

TanStack Query（React Query）现已更新，可正确配合 React Compiler 使用。

### Combined Types Inlining

`anyOf`、`oneOf` 和 `allOf` 现在默认会被内联：

```ts
// Before
export type Response401OneOf = { defined: true; ... };
export type Response401OneOfTwo = { defined: false; ... };
export type Response401 = Response401OneOf | Response401OneOfTwo;

// After
export type Response401 = { defined: true; ... } | { defined: false; ... };
```

如果你想保持之前的行为：

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      override: {
        aliasCombinedTypes: true,
      },
    },
  },
});
```

## 破坏性变更

### 1. ESM 迁移

项目现已完全从 CommonJS 转换为 ESM。

**关键变化：**
- 要求 Node.js 22.18+
- 所有 package 现在都在 `package.json` 中使用 `"type": "module"`
- 使用 `import`/`export` 语法，而不是 `require()`

**迁移方式：**

```bash
# 检查 Node.js 版本
node --version  # 应该 >= 22.18.0
```

更新配置文件（重命名或添加 type 均可）：

```bash
mv orval.config.js orval.config.mjs
```

或者在 `package.json` 中添加：

```json
{
  "type": "module"
}
```

如果你以编程方式使用 Orval，还需要更新导入方式：

```diff
- const { generate } = require('orval');
+ import { generate } from 'orval';
```

更新动态导入：

```diff
- const config = require('./orval.config.js');
+ const config = await import('./orval.config.js');
```

> 如果 `.ts` 文件本来就是按 ESM 风格编写，则无需修改。

**好处：**
- 更好的 tree-shaking（消除未使用代码）
- 原生浏览器支持
- 异步模块加载
- 更严格的模块边界

### 2. 默认 httpClient 改为 `fetch`

如有需要，请显式设置 `httpClient: 'axios'`。

### 3. 移除 `override.fetch.explode`

请直接在你的 OpenAPI 规范中指定 `explode`。

### 4. Mock delay 默认值改为 `false`

如果需要，请显式设置 `delay: 1000`。

### 5. 移除 `override.coerceTypes`

请改用 `override.zod.coerce`：

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      override: {
        zod: {
          coerce: {
            param: true,
            query: true,
            header: true,
            body: true,
            response: true,
          },
        },
      },
    },
  },
});
```

### 6. 移除 `override.useNativeEnums`

请改用 `enumGenerationType: 'enum'`。

### 7. Zod Schema 命名改为 PascalCase

```diff
- export const createPetsBody = zod.object({ ... })
+ export const CreatePetsBody = zod.object({ ... })
```

### 8. 移除 `input.validation`

`input.validation` 选项已不存在。现在会始终校验规范，并且校验器 `@scalar/openapi-parser` 相比 v7 使用的 IBM 校验器更严格，过去只是 warning 的问题现在会直接变成 hard error。

如果你的规范文件有问题并且你可以修复它，请使用 `input.override.transformer`。
它现在会在校验**之前**运行，因此你可以原地修复问题。作为最后手段，如果你确实要完全关闭校验，可以使用 `input.unsafeDisableValidation`：

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    input: {
      target: './petstore.yaml',
      unsafeDisableValidation: true,
    },
  },
});
```

详情请参考 [`input.unsafeDisableValidation`](/docs/reference/configuration/input#unsafedisablevalidation)
和 [`input.override.transformer`](/docs/reference/configuration/input#transformer)。

<Callout type="info">
  如果你的规范是 OpenAPI 2.0（Swagger），`override.transformer` 现在接收到的是 2.0 文档本身；之前它运行在升级后的 3.1 形式上。请相应调整那些假定输入为 3.x 结构的 transformer。
</Callout>

### 9. SWR 默认不生成错误类型

自定义错误类型别名（例如 `ListPetsQueryError`、`CreatePetsMutationError`）默认不再生成。

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      override: {
        swr: {
          generateErrorTypes: true,
        },
      },
    },
  },
});
```

### 10. `output.mock` 改为使用 `generators` 数组

此前，`output.mock` 可以接受 `true`，也可以接受扁平的配置对象（例如 `{ type: 'msw', delay: 1000, locale: 'fr', ... }`）。所有选项都放在一个对象里，而且 `type: 'msw'` 是唯一支持的类型。

现在，`output.mock` 会把 generator 条目放进 `generators` 数组中。每个条目都会生成自己的输出文件（例如 `.msw.ts`、`.faker.ts`）。这样一来，同一份配置就可以生成多个彼此独立的 mock 输出。

#### `mock: true` 的行为变化

`mock: true` 以前只会生成 MSW handlers。现在它会同时生成 **MSW handlers**（`.msw.ts`）和 **Faker 数据工厂**（`.faker.ts`）。如果你想保持旧行为（只生成 MSW），请使用显式写法：

```ts
output: {
  mock: { generators: [{ type: 'msw' }] },
}
```

#### 迁移扁平配置对象

所有 generator 级别的选项（`delay`、`useExamples`、`locale`、`baseUrl` 等）都需要移动到 generator 条目内部：

```diff
output: {
- mock: { type: 'msw', delay: 1000, useExamples: true, locale: 'fr' },
+ mock: {
+   generators: [{ type: 'msw', delay: 1000, useExamples: true, locale: 'fr' }],
+ },
}
```

#### `indexMockFiles` 移到外层包装对象

`indexMockFiles` 现在是 collection 级别选项，而不是 generator 级别选项：

```diff
output: {
- mock: { type: 'msw', indexMockFiles: true },
+ mock: { indexMockFiles: true, generators: [{ type: 'msw' }] },
}
```

#### 新增：仅生成 Faker 输出

如果你只想生成 Faker 数据工厂，而不生成 MSW handlers：

```ts
output: {
  mock: { generators: [{ type: 'faker' }] },
}
```

## 其他改进

### Fetch Client Headers 变量展开

现在 `override.requestOptions.headers` 已支持变量展开。

### Bug 修复

- Zod `nullable` + `$ref` 支持（符合 OpenAPI 3.1）
- 支持 `oneOf`/`anyOf` 的公共属性
- 日期参数修复
- Svelte 5 响应式支持
