从 OpenAPI 规范生成 [Zod](https://zod.dev/) schema，以便进行运行时校验。

## 配置

将 `client` 选项设为 `zod`：

```ts title="orval.config.ts"
import { defineConfig } from 'orval';

export default defineConfig({
  petstore: {
    output: {
      client: 'zod',
      mode: 'single',
      target: './src/api/schemas',
      override: {
        zod: {
          // 优先使用 Mini，以获得更好的 tree-shaking 效果。
          variant: 'mini',
          version: 4,
        },
      },
    },
    input: {
      target: './petstore.yaml',
    },
  },
});
```

## 生成结果

Orval 会为 OpenAPI 规范中的每个模型生成一个 Zod schema：

```ts
export const CreatePetsBody = /*#__PURE__*/ zod.object({
  id: /*#__PURE__*/ zod.number(),
  name: /*#__PURE__*/ zod.string(),
  tag: /*#__PURE__*/ zod.optional(/*#__PURE__*/ zod.string()),
});
```

## Tree Shaking

当启动时间、内存占用或 bundle 大小很重要时，优先使用 `variant: 'mini'`。Zod Mini 使用顶层辅助函数，因此在导出的校验器未被使用时，更容易被可靠地 tree-shake 掉：

```ts
// 常规 Zod
export const User = zod.object({
  email: zod.email().min(5).max(255),
});

// Zod Mini
export const User = /*#__PURE__*/ zod.object({
  email: /*#__PURE__*/ zod
    .email()
    .check(/*#__PURE__*/ zod.minLength(5))
    .check(/*#__PURE__*/ zod.maxLength(255)),
});
```

当 `User` 未被使用时，打包后的常规 Zod 输出仍可能把 schema 初始化保留为顶层执行代码，即使没有任何地方使用它：

```js
// 可能的常规 Zod 打包输出（没有 export const User，但 zod 调用仍然存在）
object({
  email: email().min(userEmailMin).max(userEmailMax),
});
```

使用带有 pure 注解的 Zod Mini 后，未使用的 schema 则可能被完全移除：

```js
// 可能的 Zod Mini 打包输出
// 完全没有生成 User schema 代码
```

在大型生成客户端中，这可以从最终 bundle 中移除未使用的 schema 初始化代码。在真实构建里，这可能意味着启动时少加载数百 KB 的验证代码。

## 数组响应元素

内联数组响应的元素可以使用 `allOf`、`oneOf` 或 `anyOf` 等 OpenAPI composition。Orval 会为元素类型生成 schema，例如：

```ts
export const ListAllOf200Item = zod.object({
  id: zod.int().optional(),
}).and(
  zod.object({
    extra: zod.string().optional(),
  }),
);
```

生成的 client 可以使用 `ListAllOf200Item[]` 作为响应类型。如果数组元素是 component `$ref`，则由 component schema writer 负责，不会生成重复的 operation item schema。

## Zod version

Orval 以 **Zod 4** 作为输出基线（`z.strictObject`、`z.looseObject`、`z.iso.datetime()`、`.meta()` 等），但也完全支持仍在使用 Zod 3 的项目。最终输出的语法会跟随你的项目实际解析到的 `zod` 主版本。

使用默认值（`'auto'`）时，Orval 会根据你项目 `package.json` 中解析到的 `zod` 版本来推断目标版本。如果检测不到 `zod` 包，例如在一个全新或依赖尚未完整安装的工作区中，它会回退到 **Zod 4**。

若要让生成结果保持确定性，可通过 `override.zod.version` 显式固定目标版本：

```ts title="orval.config.ts"
import { defineConfig } from 'orval';

export default defineConfig({
  petstore: {
    output: {
      client: 'zod',
      target: './src/api/schemas',
      override: {
        zod: {
          variant: 'mini',
          version: 4, // 3 | 4 | 'auto'
        },
      },
    },
    input: {
      target: './petstore.yaml',
    },
  },
});
```

| 值 | 输出 |
| --- | --- |
| `4` | 无论安装的 `zod` 版本是什么，都始终生成 Zod 4 语法。 |
| `3` | 无论安装的 `zod` 版本是什么，都始终生成兼容 Zod 3 的语法。 |
| `'auto'` | 默认值。根据解析到的 `zod` 版本自动推断；如果未检测到，则回退到 Zod 4。 |

固定版本可以保持输出稳定：同一份规范在每台机器和 CI 中都会生成相同的 schema，而不会受本地恰好安装了哪个 `zod` 版本影响。

该选项只决定输出 Zod 3 还是 Zod 4 语法。依赖特定 Zod 4 版本的输出（例如下文中启用 `generateXor` 时 `oneOf` 的 `zod.xor`）仍取决于 `zod` 的版本：已安装的版本，或在尚未安装 `zod` 时所声明版本范围的下限。若要让输出完全可复现，请声明下限已包含该特性的版本范围（`zod.xor` 需要 `^4.2.0`）。

### `oneOf` 与 `anyOf`

默认情况下，`oneOf` 和 `anyOf` 都输出为 `zod.union([...])`。`oneOf` 表示恰好只有一个分支匹配，因此可以设置 [`generateXor`](/zh/docs/reference/configuration/output#generatexor)，在 Zod 4.2 及以上版本中将其输出为 [`zod.xor([...])`](https://zod.dev/api#exclusive-unions-xor)。该选项需要显式开启，因为非 strict 的对象分支会剥离未知键，子类型的数据也会匹配其父类型（例如 `Dog` 继承 `Pet` 时的 `oneOf: [Pet, Dog]`），从而被 `zod.xor` 拒绝。`anyOf` 仍输出为 `zod.union([...])`；成员可能重叠的类型数组（`type: ['integer', 'number']`）以及表示“等于其中某个值”的混合类型 `enum` 同样保持 `zod.union`。即使启用了 `generateXor`，以下情况下 `oneOf` 仍输出为 `zod.union([...])`：

- 在没有 `xor` 的 Zod 3 和 Zod 4.0/4.1 中，或无法检测到 `zod` 版本时；
- 某个分支被[类型转换](/zh/docs/reference/configuration/output#coerce)时，因为类型转换可能使分支重叠（`"42"` 同时通过 `zod.string()` 和 `zod.coerce.number()`）；
- 某个分支的输出比规范更宽松时（`{}`、仅含 `required` 的分支，或带有 `not` 等 Orval 会丢弃的关键字），因为两个宽松的分支会同时匹配；
- 带有 `discriminator` 时；启用 [`generateDiscriminatedUnion`](/zh/docs/reference/configuration/output#generatediscriminatedunion) 时则输出为 `zod.discriminatedUnion(...)`。

## Zod Mini

将 `override.zod.variant` 设为 `'mini'`，即可针对 [Zod Mini](https://zod.dev/packages/mini) 生成 schema：

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      client: 'zod',
      override: {
        zod: {
          variant: 'mini',
          version: 4,
        },
      },
    },
  },
});
```

Mini 输出会从 `zod/mini` 导入，并使用 Zod Mini 的函数式 / check 风格 API。它要求使用 Zod 4；如果 `version: 3`，或 `version: 'auto'` 最终解析为 Zod 3，则会被拒绝。

当生成的 schema 会被打包进前端应用、Cloudflare Workers 或其他对启动成本敏感的运行时中时，优先考虑 Zod Mini，因为它更利于 tree-shaking，也更节省 bundle 体积。如果这些约束并不重要，则可以使用常规 Zod，它的链式 API 更熟悉，自动补全体验也更好。

一个行为差异是：Zod Mini 默认不会加载英文 locale。如果你想要常规 Zod 那样的默认英文报错信息，需要手动配置一次：

```ts
import * as zod from 'zod/mini';

zod.config(zod.locales.en());
```

## 不受支持的 Schema

有些 schema 的校验会比规范更宽松。默认情况下 Orval 会不加提示地生成它们。将 [`override.zod.unsupported`](/docs/reference/configuration/output#unsupported) 设为 `'error'` 可让生成直接失败。错误会指出对应的 schema，例如 `getPetResponse > owner > tags`，并说明如何关闭该检查。

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      client: 'zod',
      target: './src/api/endpoints.ts',
      override: { zod: { unsupported: 'error' } },
    },
  },
});
```

`'error'` 模式下以下情形会失败。某个设置能解决的情形，错误会指出该设置。没有 [`strict`](/docs/reference/configuration/output#strict) 的 `additionalProperties: false` 不会报错。

- 没有 Zod 对应项的关键字：`not`（空的除外，以及在与同级 `properties` 并列的 `oneOf`/`anyOf` 分支中只禁止某些键的 `not`）、`if`/`then`/`else`、`patternProperties`、`propertyNames`、`dependentSchemas`、`dependencies`、`unevaluatedProperties`、`unevaluatedItems`、`contains`、`minContains`、`maxContains`、`uniqueItems`、`minProperties`、`maxProperties`、`additionalItems` 和 `contentSchema`。`dependentRequired` 在无法生成的位置会失败：没有属性的对象，或与组合关键字并列。
- 没有 `type` 的 schema 上的约束（`minimum`、`minLength`、`pattern`、`items` 等）、对象或数组的 `const`，以及写成列表的 `items`。
- 生成为普通 union 的 `oneOf`，除非其备选项的类型、字面量或 discriminator 值互不相同。未开启 [`generateXor`](/docs/reference/configuration/output#generatexor) 时，错误会提示开启它。带有强制类型转换（coerce）的备选项同样会使 `oneOf` 生成为普通 union。
- 同一 schema 上有多个组合关键字，因为只会生成 `allOf`、`oneOf`、`anyOf` 中的第一个。
- 在 `strict` 或 discriminated union 中被合并为一个对象的 `allOf` 对象成员，以不同方式声明同一属性或 `additionalProperties`：合并只保留一个定义。收窄先前类型或枚举的字面量或枚举会被接受。
- 请求体或响应根部的数组带有 `prefixItems`、`null`、`enum`、`const`、组合关键字或 `format`：只会生成其元素和长度限制。
- 无法解析的 `$ref` 或 `$dynamicRef`，以及被内联的循环 `$ref`，因为它们会被当作 unknown 校验。未开启 [`generateReusableSchemas`](/docs/reference/configuration/output#generatereusableschemas) 时，错误会提示开启它。
- zod 不校验的 `format`（例如 `format: phone`），`formatType` 映射的格式除外。受校验的格式为 `date`、`time`、`time-local`、`date-time`、`date-time-local`、`email`、`uri`、`hostname`、`uuid`、`ipv4`、`ipv6` 和 `binary`，以及通过数字类型校验的 `int32`、`int64`、`float` 和 `double`。`contentEncoding`（例如 `base64`）同样不会被校验。

## 按 operation 或 tag 作用域化配置

大多数 `override.zod` 选项都可以只应用到 API 的一部分，而不是全局生效。可通过 `override.operations[operationId].zod` 为单个 operation 配置，或通过 `override.tags[tagName].zod` 为共享同一 tag 的所有 operation 配置：

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      client: 'zod',
      override: {
        zod: {
          variant: 'mini',
          version: 4,
          strict: { response: true }, // 全局生效
        },
        operations: {
          listPets: {
            zod: {
              coerce: { query: ['number'] }, // 仅此 operation
            },
          },
        },
        tags: {
          admin: {
            zod: {
              strict: { body: true }, // 所有带有 "admin" tag 的 operation
            },
          },
        },
      },
    },
  },
});
```

按 operation 和按 tag 的 override 仅接受那些能作用于单个 schema 的选项：`strict`、`generate`、`coerce`、`preprocess`、`params`、`useBrandedTypes` 和 `generateCompanionTypes`。

而面向整个输出的选项，如 `variant`、`version`、`dateTimeOptions`、`timeOptions`、`generateEachHttpStatus`、`generateReusableSchemas`、`generateMeta`、`generateDiscriminatedUnion`、`generateXor`、`exactOptional` 和 `unsupported`，只适用于整个输出，因此必须保留在 `override.zod` 下。如果你把这些选项写到 operation 或 tag 上，它们会被忽略，实际仍使用 `override.zod` 中的值，同时 Orval 会输出一条构建警告：

```
⚠️ override.operations.listPets.zod only supports strict, generate, coerce, preprocess, params, useBrandedTypes, and generateCompanionTypes. Ignoring unsupported field: zod.version.
```

## 与 Model 对照检查

Model 和 schema 由不同的生成器生成，两者可能在无人察觉时产生偏差。如果项目在另一个配置中生成 TypeScript model，共享选项 [`override.modelTypeChecks`](/zh/docs/reference/configuration/output#modeltypechecks)（也适用于 [Valibot](/zh/docs/guides/valibot#与-model-对照检查)）会让 schema 文件断言每个组件 schema 的输出类型与其 model 一致。它需要 `generateReusableSchemas`，并且只在 schema 与 operation 写在一起时可用，即不设置 `output.schemas`：

```ts title="orval.config.ts"
export default defineConfig({
  api: {
    output: {
      client: 'fetch',
      target: './src/api/endpoints.ts',
      schemas: './src/api/model',
    },
    input: { target: './petstore.yaml' },
  },
  validation: {
    output: {
      client: 'zod',
      target: './src/validation/schemas.ts',
      override: {
        zod: { generateReusableSchemas: true },
        modelTypeChecks: { models: './src/api/model' },
      },
    },
    input: { target: './petstore.yaml' },
  },
});
```

`models` 是另一个配置写入 model 的目录，与它的 `output.schemas` 相同。相对路径从当前配置的 workspace 开始，它可能与另一个配置的 workspace 不同；绝对路径按原样使用。schema 文件会导入该目录，并多出一个仅用于类型的代码块，运行时不受影响：

```ts
import type * as Models from '../api/model';

type Assert<T extends true> = T;
type Extends<A, B> = [A] extends [B] ? true : false;
type SchemaModelTypeChecks = {
  Pet: [
    Assert<Extends<zod.output<typeof Pet>, Models.Pet>>,
    Assert<Extends<Models.Pet, zod.output<typeof Pet>>>,
  ];
};
declare const schemaModelTypeChecks: SchemaModelTypeChecks;
```

该类型不会导出，因此重新导出多个此类文件的 barrel 不会因它而冲突。环境声明 `declare const` 会读取该类型，因此 `noUnusedLocals` 不会报错，且不产生任何代码。

当 schema 与其 model 无法双向赋值时，你自己的 `tsc` 会在该组件的断言处报错：`Type 'false' does not satisfy the constraint 'true'`。检查读取的是 `zod.output`，Zod 3、Zod 4 和 Zod Mini 都有它。

- 两个配置必须使用相同的命名选项，例如 `override.components.schemas`，这样 model 才与 schema 同名。
- 双向可赋值无法发现只在一侧声明的可选属性，也无法发现任一侧为 `any` 的类型。必填属性、可空性、枚举、联合类型以及嵌套类型都能被检出。
- 递归组件是与其常量所标注的类型对照检查的，该类型由 Orval 通过 model 生成器写出，因此只有两者对组件本身的处理出现偏差时才会在此显现。
- 检查会导入 models 的 `index.ts`，并要求它按名称导出每个组件。请在生成 model 的配置中保持 `indexFiles` 开启（默认即开启）。
- 在 schema 中映射类型的选项，例如 `formatType` 或 `useDates`，在 model 中也必须做同样的映射。请在两个配置中都设置 `useBigInt` 和 `useReadonlyArrays`，这样检查会跳过它们所改变的组件。
- 如果 `tsconfig` 中启用了 `exactOptionalPropertyTypes`，model 会把可选属性写为 `a?: T`，因此请在 `override.zod` 中设置 `exactOptional: true`，否则每个可选属性都会检查失败。这需要 Zod 4.3 或更高版本，因为 Zod 3 以及 Zod 4.0 到 4.2 没有 `.exactOptional()`。当 Orval 读取的 `tsconfig` 启用了该选项而 `exactOptional` 未开启时，或检测到的 Zod 版本低于 4.3（`exactOptional` 的任何设置都无法满足该选项：请升级 Zod，或设置 `exactOptional: false` 并关闭该选项）时，生成时会给出警告。
- `modelTypeChecks` 会拒绝 `useBrandedTypes`、`useNullForOptional` 和 `enumGenerationType: 'enum'` 并报错，因为它们会让 model 出现 Zod 输出无法匹配的形态。schema 输出的字符串字面量不能赋值给 TypeScript `enum`，因此生成 model 的配置中也请使用 `'const'` 或 `'union'`。`namingConvention.properties` 可以使用，因为 Zod 会像 model 一样重命名其输出的键。

### 被跳过的组件

Orval 有意让某些 schema 的类型比 model 更宽松，因此在这些地方没有任何 schema 能与 model 一致。包含这类写法的组件不会生成断言，代码块中会有一条注释说明原因，文件仍可正常编译：

```ts
type SchemaModelTypeChecks = {
  Pet: [
    Assert<Extends<zod.output<typeof Pet>, Models.Pet>>,
    Assert<Extends<Models.Pet, zod.output<typeof Pet>>>,
  ];
  // Labels: skipped, a readOnly array is readonly in the model, which the schema output is not
};
declare const schemaModelTypeChecks: SchemaModelTypeChecks;
```

引用了被跳过组件的组件也会被跳过，因为它的输出类型包含对方的类型。这些写法包括：

- 带 `items` 的 `readOnly` 数组在 model 中是 `readonly T[]`，而 Zod schema 的输出是 `T[]`。
- 可选属性上的 `default` 只让输出中的键变为必填。
- `properties` 旁边的 `additionalProperties` 在 model 中是 `unknown` 类型，而 schema 会校验它。
- 没有类型的 schema，例如 `{}` 或只有 `description` 的 schema，按 `unknown` 校验，而 model 将其类型写为 `{}`。
- 没有类型、只带 `patternProperties`、空 `properties` 或 `additionalProperties: false` 的组件按 `unknown` 校验，而 model 将其类型写为对象。Zod 会为带 schema 或 `true` 的 `additionalProperties` 保留 record，属性或成员中的这类 schema 在 model 中同样没有类型。
- 值为对象或数组的 `const` 不会被校验。
- 类型中含 `null` 的 `const`，model 会去掉 `null`。
- 所有属性都是 `const` 的组件，model 会写成常量对象，因此每个键都是必填。带有可选 `const` 属性的组件与 schema 不一致。
- 在同一 schema 的 `properties` 或 `allOf` 旁边，`oneOf` 或 `anyOf` 含有 `null`、可空或 `enum` 的备选项：model 会合并备选项并丢弃枚举旁的自有属性，而 schema 做交叉。
- 在同一 schema 的 `properties` 旁边，`allOf` 含有 `enum` 成员：model 把该成员与自有属性做成备选项，而 schema 做交叉。
- 指向整个组件 schema 以外目标的 `$ref`，例如 `#/paths/...` 或 `#/components/responses/...`，会按 `unknown` 校验。
- 与对象的 `properties` 并列、只要求若干键的 `oneOf` 或 `anyOf` 分支，例如 `{ required: [id] }`，会按带有这些键的对象校验，而 model 将其类型写为 `unknown`。
- 启用 `useBigInt` 时，64 位整数（`format: int64` 或 `uint64`）在 model 中是 `bigint`，在 schema 中是 `number`。
- 启用 `useReadonlyArrays` 时，数组在 model 中是 `readonly`，而 schema 的输出不是。
- 带有 `items` 的元组（`prefixItems`），若其 `maxItems` 不大于前缀项的数量，model 会保留其剩余元素类型，而 schema 会省略它们。
- 经过元组（`prefixItems`）的循环引用：Zod 只内联一层，之后将其验证为 `unknown`，因此位于这种环上的组件没有断言。
- 非对象类型的 `type` 含 `null`（`'null'` 或 `['null', 'string']`）并与 `allOf`、`oneOf` 或 `anyOf` 同级：Zod 只验证组合部分，会丢弃 `null`。`['object', 'null']` 会保留 `null`，仍有断言。
- 使用 Zod 3 时，没有类型的必填属性（`{}`、`true` 或对它的引用、只有 `description` 或 `not` 的 schema、`additionalProperties: false` 这类对象形状，或含此类成员的 `oneOf`）在输出中是可选的，而 model 要求它必填；属性和 `required` 列表位于不同的 `allOf` 成员中时也是如此。Zod 4 会保持该键必填。
- 使用 Zod 3 时，没有原始类型成员的 `enum`（空，或只含对象和数组）会被验证为 `never`。
- 与字符串 `format`（`email`、`uuid` 等）同级的 `const` 会被验证为该 format，而不是字面量；带 `const` 的二进制字符串（`format: binary`，或没有 `contentEncoding` 的 `contentMediaType: application/octet-stream`）会被验证为文件。
- 没有 `prefixItems` 的 `items: false` 在 model 中是 `unknown[]`，在 schema 中是 `never[]`。
- 空 schema 的 `not`（`not: {}`）会被验证为 `never`，而 model 将其类型写为 `unknown`。
- 非对象的 `type` 与 `allOf` 同级，且该 `allOf` 的成员全是 `true`（类型不是标量时也可以是 `{}`），或与带有可接受任何值的候选项（如 `{}` 或 `true`）的 `oneOf`、`anyOf` 同级：schema 会被验证为 `unknown`，而 model 保留该类型。
- 在没有 `properties` 和 `additionalProperties` 的 schema 上，带 schema 的 `unevaluatedProperties` 只有 model 会为其定类型。
- `multipart/form-data` 请求体中带有媒体类型的字符串部分（来自 `encoding.<part>.contentType` 或自身的 `contentMediaType`，如 `image/png`、`application/json`），在 model 中会放宽为文件或字符串，而 schema 验证的是字符串。数组部分的元素，以及在请求体内联的 `allOf`、`oneOf` 或 `anyOf` 成员中声明的部分同样如此；`format: binary`、带 `const`、带 `contentEncoding` 的字符串和嵌套对象的属性不受影响。

有些情况无法被检测，因此检查仍可能失败：在递归 `allOf` 上使用 `override.zod.coerce`，在声明了同名但定义不同的键的 `allOf` 成员上使用 `override.zod.strict`，以及与全局类型同名的组件，例如启用 `useDates` 时名为 `Date` 的组件。

## 用法

### 解析数据

```ts
import { CreatePetsBody } from './src/api/schemas';

const pet = { id: 1, name: 'Buddy', tag: 'dog' };
const parsedPet = CreatePetsBody.parse(pet);
// => { id: 1, name: "Buddy", tag: "dog" }
```

### 类型推导

```ts
import type { z } from 'zod/mini';
import { CreatePetsBody } from './src/api/schemas';

type Pet = z.infer<typeof CreatePetsBody>;

const pet: Pet = { id: 1, name: 'Buddy', tag: 'dog' };
```

### 安全解析

```ts
const result = CreatePetsBody.safeParse(unknownData);

if (result.success) {
  console.log(result.data);
} else {
  console.error(result.error);
}
```
