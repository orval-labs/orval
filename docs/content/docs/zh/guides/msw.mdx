根据你的 OpenAPI 规范生成 [MSW (Mock Service Worker)](https://mswjs.io/) Handlers（请求处理器），以便在开发和测试期间生成 API Mock。

对于不带 MSW 请求 Handlers（请求处理器）的 Mock 数据工厂，请参见 [Faker guide（Faker 指南）](/docs/guides/faker)。

## 配置

将 `mock` 选项设为 `true`（同时生成 MSW Handlers 和 Faker Factories），或者通过 Generator 条目把它限定为只生成 MSW：

```ts title="orval.config.ts"
import { defineConfig } from 'orval';

export default defineConfig({
  petstore: {
    output: {
      mode: 'single',
      target: './src/api/petstore.ts',
      schemas: './src/api/model',
      mock: {
        generators: [{ type: 'msw' }],
      },
    },
    input: {
      target: './petstore.yaml',
    },
  },
});
```

## 生成结果

MSW 生成器会为每个操作生成两类函数，以及一个聚合器。mock **数据**（即 `get<Op>ResponseMock` factories）由 Faker 生成器负责生成。关于如何覆盖值和格式，请参见 [Faker guide](/docs/guides/faker)。

### 1. 请求 Handlers

这些函数会把 Mock 数据绑定到 [MSW](https://mswjs.io/) 的 `http.*` handlers（处理器）上，并使用推荐的 [`HttpResponse`](https://mswjs.io/docs/api/http-response) 类：

```ts
import { HttpResponse, delay, http } from 'msw';
import type { RequestHandlerOptions } from 'msw';

export const getShowPetByIdMockHandler = (
  overrideResponse?:
    | Pet
    | ((info: Parameters<Parameters<typeof http.get>[1]>[0]) => Promise<Pet> | Pet),
  options?: RequestHandlerOptions,
) => {
  return http.get('*/pets/:petId', async (info) => {
    await delay(1000);
    return HttpResponse.json(
      overrideResponse !== undefined
        ? typeof overrideResponse === 'function'
          ? await overrideResponse(info)
          : overrideResponse
        : getShowPetByIdResponseMock(),
      { status: 200 },
    );
  }, options);
};
```

Orval 会根据你的 OpenAPI 规范中的 content type（内容类型）选择合适的 `HttpResponse` helper。如果定义了多个 content type（内容类型），你可以设置一个首选默认值；否则会按规范中的顺序使用：

| Content type | Response helper |
|---|---|
| `application/json` | `HttpResponse.json()` |
| `application/xml`, `*+xml` | [`HttpResponse.xml()`](https://mswjs.io/docs/api/http-response) |
| `text/html` | [`HttpResponse.html()`](https://mswjs.io/docs/api/http-response) |
| `text/plain`, other `text/*` | `HttpResponse.text()` |
| `application/octet-stream`, `image/*`, etc. | `HttpResponse.arrayBuffer()` |
| No body (204, etc.) | `new HttpResponse(null, { status })` |

如果在定义了多个 content type（内容类型）时想优先使用某个特定类型（例如优先 JSON 而不是 XML），请设置 `mock.preferredContentType`：

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      mock: {
        generators: [
          {
            type: 'msw',
            preferredContentType: 'application/json',
          },
        ],
      },
    },
  },
});
```

`preferredContentType` 接受常见的 MIME 字面量，也接受任意自定义字符串（通过宽松的 `(string & {})` 回退），因此同样支持 vendor-specific type（厂商自定义类型）。

`preferredContentType` 只会**选择**一个已声明的 media type（媒体类型），并不会转换 payload（载荷）。如果你选择的 media type（媒体类型）不在该操作的响应定义中，这个偏好会被忽略，并改用规范顺序。当响应 schema 是结构化对象或数组时，应优先选择 JSON media type：如果把非 JSON 偏好（例如 `text/plain` 或 `application/xml`）和结构化 schema 搭配使用，返回的会是字符串化 body，而 `application/octet-stream` 则会回退为 JSON，并把选中的 media type 作为 `Content-Type`。

### 数组项工厂

在 MSW generator 条目上设置 `arrayItems: true`，即可为操作响应中的对象型数组项 schema 生成可复用的 mock 工厂（例如针对 `value: TenantResponseModelDto[]` 生成 `getTenantResponseModelDtoMock`）。这些工厂会和 handlers、response mocks 一起写入同一个 `.msw.ts` / endpoints mock 文件。有关配置细节和支持的结构，请参见 [Faker guide — Array Item Factories](/docs/guides/faker#array-item-factories)。

```ts title="orval.config.ts"
mock: {
  generators: [
    {
      type: 'msw',
      arrayItems: true,
    },
  ],
}
```

### 2. 聚合 Handlers

这些函数会把所有 handlers（处理器）组合在一起，便于快速接入：

```ts
export const getPetsMock = () => [
  getListPetsMockHandler(),
  getCreatePetsMockHandler(),
  getShowPetByIdMockHandler(),
];
```

## 用法

### 基础设置

将聚合后的 handler 函数与 MSW 的 [`setupServer`](https://mswjs.io/docs/api/setup-server)（Node.js）或 [`setupWorker`](https://mswjs.io/docs/api/setup-worker)（浏览器）一起使用：

```ts
import { getPetsMock } from './api/petstore.msw';
import { setupServer } from 'msw/node';

const server = setupServer(...getPetsMock());

beforeAll(() => server.listen());
afterEach(() => server.resetHandlers());
afterAll(() => server.close());
```

### 自定义响应

直接传入静态数据：

```ts
const showPetByIdMockHandler = getShowPetByIdMockHandler({
  id: 1,
  name: 'Custom Pet',
  tag: 'custom',
});
```

### 动态响应

传入函数，根据请求数据动态生成响应：

```ts
getShowPetByIdMockHandler(async (info) => {
  const petId = info.params.petId;
  return { id: Number(petId), name: `Pet ${petId}`, tag: 'dynamic' };
});
```

### 使用 `server.use()` 覆盖（MSW 最佳实践）

遵循 [MSW 对网络行为覆盖的最佳实践](https://mswjs.io/docs/best-practices/network-behavior-overrides)，在单个测试中使用 `server.use()` 覆盖特定 handlers（处理器），同时保留默认的 happy-path handlers（成功路径处理器）：

```ts
import { http, HttpResponse } from 'msw';

it('handles server error', () => {
  server.use(
    getShowPetByIdMockHandler(() => {
      throw new HttpResponse(null, { status: 500 });
    }),
  );

  // Test error UI...
});
```

### 传递 MSW `RequestHandlerOptions`

每个生成的 handler 都接受一个可选的第二个 `options` 参数（例如 `{ once: true }`）：

```ts
server.use(
  getShowPetByIdMockHandler(myOverride, { once: true }),
);
```

### 使用 Vitest 测试

```ts
import { expect, vi } from 'vitest';
import { getShowPetByIdMockHandler, getShowPetByIdResponseMock } from './api/petstore.msw';

const mockFn = vi.fn();

const handlers = [
  getShowPetByIdMockHandler(async (info) => {
    mockFn(info.params.petId);
    return getShowPetByIdResponseMock();
  }),
];

// ... run test

expect(mockFn).toHaveBeenCalledWith('123');
```

## Base URL

默认情况下，handlers（处理器）会使用通配的 `*` 前缀（例如 `*/pets/:petId`），因此它们可以匹配任意 host（主机）。如果你想使用特定的 base URL，请在 MSW generator 条目上设置 `baseUrl`：

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      mock: {
        generators: [
          {
            type: 'msw',
            baseUrl: 'https://api.example.com',
          },
        ],
      },
    },
  },
});
```

这会生成类似 `http.get('https://api.example.com/pets/:petId', ...)` 的 handlers，这也符合 MSW 关于使用[绝对 URL](https://mswjs.io/docs/http/intercepting-requests)进行精确匹配的建议。

## 动态导入

在 `split` 和 `tags-split` 模式下，启用 `mock.indexMockFiles` 可以为每个 generator 条目生成一个根级别的 `index.<ext>.ts` 文件。对于 MSW 条目，会生成一个可供动态导入的 `index.msw.ts`。这样可以把 MSW 保持在独立的 barrel 中，而不会被你的生产/model barrel 重新导出。这在 `jsdom`/`vitest` 环境下尤其有用，因为 MSW 在模块求值阶段会引用 stream globals：

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      mode: 'tags-split',
      mock: {
        indexMockFiles: true,
        generators: [{ type: 'msw' }],
      },
    },
  },
});
```

```ts
// node.ts
import * as mocks from './endpoints/index.msw';
import { setupServer } from 'msw/node';

const handlers = Object.entries(mocks).flatMap(([, getMock]) => getMock());
const server = setupServer(...handlers);

export { server };
```

如果同时为 `msw` 和 `faker` 生成器配置了 `indexMockFiles: true`，你还会得到一个与 `index.msw.ts` 并列的 `index.faker.ts`。

## MSW 最佳实践

生成的代码遵循 [MSW best practices](https://mswjs.io/docs/best-practices)：

- **`HttpResponse` 类**：使用 `HttpResponse.json()`、`.xml()`、`.html()`、`.text()` 和 `.arrayBuffer()`，而不是直接使用原始 `Response` 构造函数，这也是 [MSW 推荐的方式](https://mswjs.io/docs/api/http-response)。当设置了 `mock.preferredContentType` 时，会优先根据它选择 helper；否则会选择 OpenAPI 规范中第一个匹配的 content type。
- **`delay()` 函数**：使用独立导入的 `delay()`（而不是旧的 `ctx.delay`），并且可以按操作或全局配置。
- **Handler 结构**：每个 handler 都是一个返回 `http.get/post/...()` 的工厂函数，因此可以直接展开传给 `setupServer()` 或 `setupWorker()`。
- **运行时覆盖**：在测试中使用 [MSW 的 `server.use()`](https://mswjs.io/docs/best-practices/network-behavior-overrides) 来覆盖单个 handler。生成的 handler 工厂使这种做法非常直接。
- **谓词中不包含 query parameters**：路径谓词永远不会包含 query string，这符合 [MSW 的指导](https://mswjs.io/docs/http/intercepting-requests)。
- **路径参数**：OpenAPI 的 `{param}` 会被转换为 MSW 的 `:param` 语法，以实现正确匹配。
