---
title: MCP Server（MCP 服务端）
description: 从 OpenAPI 生成 Model Context Protocol（MCP）服务端
---

根据你的 OpenAPI 规范生成 [Model Context Protocol (MCP)](https://modelcontextprotocol.io/introduction) 服务端，以便集成到 AI Agent（智能体）中。

## 概览

MCP 服务端会将 API 客户端提供给 AI Agent（智能体）使用，这样你就不需要等待第三方实现。你可以为任何带有 OpenAPI 规范的服务创建 MCP 服务端，并将其与 Claude、Cline 等 AI Agent 一起使用。

## 配置

```ts title="orval.config.ts"
import { defineConfig } from 'orval';

export default defineConfig({
  petstore: {
    input: {
      target: './petstore.yaml',
    },
    output: {
      mode: 'single',
      client: 'mcp',
      baseUrl: 'https://petstore3.swagger.io/api/v3',
      target: 'src/handlers.ts',
      schemas: 'src/http-schemas',
    },
  },
});
```

<Callout type="info">
`mcp` Client 目前仅支持在 `single` 模式下使用。
</Callout>

## 生成结构

```
src/
├── http-schemas/
│   ├── createPetsBodyItem.ts
│   ├── error.ts
│   ├── index.ts
│   └── pet.ts
├── handlers.ts         # 返回 MCP 格式的 handler 函数
├── http-client.ts      # 生成的 fetch client
├── server.ts           # MCP tools 和服务端配置
└── tool-schemas.zod.ts # tool 输入的 Zod schema
```

## 用法

### 1. 构建 Docker 镜像

```bash
docker build ./ -t mcp-petstore
```

### 2. 配置 AI Agent（智能体）

以 Cline 为例：

```json
{
  "mcpServers": {
    "petstore": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "mcp-petstore"],
      "disabled": false,
      "alwaysAllow": []
    }
  }
}
```

这样你的 AI Agent（智能体）就可以通过 MCP 协议与该 API 交互。

## Request Cancellation（请求取消）

当 MCP 客户端取消工具调用时，生成的 `server.ts` 会把该调用的取消信号传递给底层 HTTP 请求，正在进行的 `fetch` 会以 `AbortError` 中止。通过 `createMcpServer(options)` 传入的 `signal` 会与每次调用的信号用 `AbortSignal.any` 合并，任一信号触发都会中止请求。运行环境需要 Node.js 20.3 或更高版本。

```ts title="src/server.ts (generated)"
tools.findPetsByStatus = server.registerTool(
  'findPetsByStatus',
  {
    // ...
  },
  (args, ctx) =>
    findPetsByStatusHandler(args, {
      ...options,
      signal: options?.signal
        ? AbortSignal.any([options.signal, ctx.signal])
        : ctx.signal,
    }),
);
```

如果通过 `createMcpServer(options)` 传入 `signal`，例如在自定义 Server 中希望在关闭时中止所有进行中的请求，该信号会通过 `AbortSignal.any` 与每次调用的信号合并。任一信号中止，相关请求都会被取消。

```ts title="custom-server.ts"
const shutdown = new AbortController();
const { server } = createMcpServer({ signal: shutdown.signal });
process.on('SIGTERM', () => shutdown.abort());
```

<Callout type="info">
运行时需要 Node.js 20.3 或更高版本才能使用 `AbortSignal.any`。
</Callout>

## Custom Handler（自定义 Handler）

默认情况下，每个生成的 handler 会把响应体作为文本返回，将 400 及以上的 HTTP 状态码标记为错误，并把解析后的响应体作为 `structuredContent` 返回。如果你想自行控制响应整形和错误映射，或者想利用工具调用上下文来做日志、鉴权或 elicitation，可以通过 `override.mcp.handler` 提供自定义 handler。

```ts title="orval.config.ts"
import { defineConfig } from 'orval';

export default defineConfig({
  petstore: {
    input: {
      target: './petstore.yaml',
    },
    output: {
      mode: 'single',
      client: 'mcp',
      baseUrl: 'https://petstore3.swagger.io/api/v3',
      target: 'src/handlers.ts',
      schemas: 'src/http-schemas',
      override: {
        mcp: {
          handler: {
            path: './custom-handler.ts',
            name: 'customHandler',
          },
        },
      },
    },
  },
});
```

设置后，每个生成的 handler 会把工具参数绑定到一个 `fetcher`，并连同工具调用上下文一起委托给你的函数：

```ts title="src/handlers.ts (generated)"
import { customHandler } from '../custom-handler';
import type { RequestHandlerExtra } from '@modelcontextprotocol/sdk/shared/protocol.js';
import type {
  ServerNotification,
  ServerRequest,
} from '@modelcontextprotocol/sdk/types.js';

export const findPetsByStatusHandler = async (
  args: findPetsByStatusArgs,
  options?: RequestInit,
  ctx?: RequestHandlerExtra<ServerRequest, ServerNotification>,
) => {
  const fetcher = (overrides?: RequestInit) =>
    findPetsByStatus(args.queryParams, {
      ...options,
      ...overrides,
      headers: {
        ...Object.fromEntries(new Headers(options?.headers)),
        ...Object.fromEntries(new Headers(overrides?.headers)),
      },
    });

  return customHandler(fetcher, ctx);
};
```

请按下面的签名实现 handler。它的返回值会直接作为工具结果使用，因此当工具声明了 `outputSchema` 时，成功路径必须返回 `structuredContent`：

```ts title="custom-handler.ts"
import type { RequestHandlerExtra } from '@modelcontextprotocol/sdk/shared/protocol.js';
import type {
  CallToolResult,
  ServerNotification,
  ServerRequest,
} from '@modelcontextprotocol/sdk/types.js';

export const customHandler = async (
  fetcher: (
    overrides?: RequestInit,
  ) => Promise<{ status: number; data: unknown; headers: Headers }>,
  ctx?: RequestHandlerExtra<ServerRequest, ServerNotification>,
): Promise<CallToolResult> => {
  const res = await fetcher({
    headers: ctx?.sessionId ? { 'Mcp-Session-Id': ctx.sessionId } : undefined,
  });

  if (res.status >= 400) {
    return {
      content: [
        {
          type: 'text',
          text: JSON.stringify({
            requestId: ctx?.requestId,
            status: res.status,
            error: res.data ?? null,
          }),
        },
      ],
      isError: true,
    };
  }

  return {
    content: [{ type: 'text', text: JSON.stringify(res.data ?? null) }],
    structuredContent: res.data as Record<string, unknown>,
  };
};
```

`fetcher` 已经绑定了工具参数以及传给 `createMcpServer` 的 `RequestInit`，其中包含上文描述的取消信号。传入 overrides 可以追加请求头或替换信号。overrides 中的请求头会合并到基础请求头中而不是整体替换，因此通过 `createMcpServer(options)` 设置的 `Authorization` 等请求头仍会保留在请求上。

`ctx` 是 SDK 为当前工具调用提供的 `RequestHandlerExtra`，包含 `signal`、`requestId`、`sessionId`、`authInfo`、`requestInfo`、`sendNotification` 和 `sendRequest`。它是可选参数，因此生成的 handler 仍然可以被直接调用，例如在测试中。

<Callout type="info">
请把自定义 handler 文件放在生成输出目录之外。如果设置了 `clean: true`，orval 每次运行都会删除输出目录，因此会移除其中的任何文件。
</Callout>

## Custom Server（自定义服务端）

默认情况下，生成的 `server.ts` 会通过 `StdioServerTransport` 建立连接。如果你想使用不同的 transport（传输方式，例如用于容器部署的 Streamable HTTP），可以通过 `override.mcp.server` 提供自定义 Server 函数。

```ts title="orval.config.ts"
import { defineConfig } from 'orval';

export default defineConfig({
  petstore: {
    input: {
      target: './petstore.yaml',
    },
    output: {
      mode: 'single',
      client: 'mcp',
      baseUrl: 'https://petstore3.swagger.io/api/v3',
      target: 'src/handlers.ts',
      schemas: 'src/http-schemas',
      override: {
        mcp: {
          server: {
            path: './custom-server.ts',
            name: 'customServer',
          },
        },
      },
    },
  },
});
```

生成的 `server.ts` 会把一个 `createMcpServer` 工厂传给你的函数：

```ts title="src/server.ts (generated)"
import { customServer } from '../custom-server';

const createMcpServer = (
  options?: RequestInit,
): { server: McpServer; tools: Record<string, RegisteredTool> } => {
  // ...tool registrations
};

customServer(createMcpServer);
```

你可以实现这个自定义 Server 函数，以建立任意 transport（传输方式）。下面的例子使用 [Hono](https://hono.dev) 和 [`@hono/mcp`](https://github.com/honojs/middleware/tree/main/packages/mcp) 来提供 Streamable HTTP：

```ts title="custom-server.ts"
import type {
  McpServer,
  RegisteredTool,
} from '@modelcontextprotocol/sdk/server/mcp.js';
import { StreamableHTTPTransport } from '@hono/mcp';
import { Hono } from 'hono';

export const customServer = (
  createMcpServer: (options?: RequestInit) => {
    server: McpServer;
    tools: Record<string, RegisteredTool>;
  },
) => {
  const app = new Hono();
  const { server } = createMcpServer();
  const transport = new StreamableHTTPTransport();

  app.all('/mcp', async (c) => {
    if (!server.isConnected()) {
      await server.connect(transport);
    }
    return transport.handleRequest(c);
  });

  Bun.serve({ fetch: app.fetch, port: Number(process.env.PORT ?? 3000) });
};
```

<Callout type="info">
请把自定义 server 文件放在生成输出目录之外。如果设置了 `clean: true`，orval 每次运行都会删除输出目录，因此会移除其中的任何文件。
</Callout>
