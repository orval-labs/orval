---

从 OpenAPI 规范生成 [Valibot](https://valibot.dev/) schema，用于运行时校验。

## 配置

将 `client` 选项设置为 `valibot`：

```ts title="orval.config.ts"
import { defineConfig } from 'orval';

export default defineConfig({
  petstore: {
    output: {
      client: 'valibot',
      mode: 'single',
      target: './src/api/schemas.ts',
    },
    input: {
      target: './petstore.yaml',
    },
  },
});
```

## 生成结果

Orval 会为每个 operation 的 params、query、headers、body 和 response 各生成一个 Valibot schema。body 和 response 的 schema 来自 JSON、`multipart/form-data` 或 `application/x-www-form-urlencoded` 内容，response 依次查看 `200`、`2XX`/`2xx` 和其他 2xx 响应（`204` 和 `205` 除外），取第一个带有上述内容的响应。其他媒体类型（例如 `text/plain`）不会生成 schema：

```ts
import * as v from 'valibot';

export const CreatePetsBody = v.object({
  id: v.pipe(v.number(), v.integer()),
  name: v.string(),
  tag: v.optional(v.string()),
});
```

## 选项

选项位于 [`override.valibot`](/docs/reference/configuration/output#overridevalibot)：

- `strict` - 按位置（`param`、`query`、`header`、`body`、`response`）生成 `v.strictObject` 而不是 `v.object`。默认全部为 `false`。
- `generate` - 按位置选择是否生成 schema。默认全部为 `true`。
- `exactOptional` - 可选属性使用 `v.exactOptional`，适用于启用了 `exactOptionalPropertyTypes` 的项目。默认 `false`。也可以按 operation 或按 tag 设置。
- `generateReusableSchemas` - 每个组件 schema 只生成一次并通过引用复用，而不是内联每个 `$ref`。默认 `false`。参见[可复用 Schema](#可复用-schema)。

## 可复用 Schema

默认情况下每个 `$ref` 都会被内联，共享组件很多的规范会让输出变得很大。设置 `generateReusableSchemas` 后，每个 `#/components/schemas/*` 条目都会生成一个导出的常量：

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      client: 'valibot',
      target: './src/api/schemas.ts',
      override: { valibot: { generateReusableSchemas: true } },
    },
    input: { target: './petstore.yaml' },
  },
});
```

```ts
export type Pet = {
  name: string;
  friends?: Pet[] | undefined;
};

export type PetInput = {
  name: string;
  friends?: PetInput[] | undefined;
};

export const Pet = v.object({
  name: v.string(),
  friends: v.optional(
    v.array(v.lazy((): v.GenericSchema<PetInput, Pet> => Pet)),
  ),
});

export const ListPetsResponse = v.array(Pet);
```

常量写在 operation 旁边：`single` 模式写入 target，其他模式写入 `*.schemas.ts` 文件。闭合循环的引用通过 `v.lazy` 读取。

循环上的每个常量还会导出两个类型：输出类型 `Pet` 和输入类型 `PetInput`。`v.lazy` 的 getter 使用这两个类型，因此递归字段的类型为 `Pet[]`，而不是 `unknown`。如果已有 schema 名为 `PetInput`，输入类型会改名为 `PetInput2`。由内联 `formatType` `decode`（例如 `(value) => dayjs(value)`）转换的字段在这些类型中为 `unknown`。改为填写函数名（例如 `'dayjs'`），即可使用该函数的返回类型。

### 限制

- 使用 `client: 'valibot'` 时，`generateReusableSchemas` 不能与 `output.schemas` 同时设置：生成时会报错。要把 schema 写入单独的模块，请在 HTTP client 上把 `schemas.type` 设为 `valibot`（同时需要 `schemas.path`）。
- 当常量的校验结果可能不同时，`$ref` 仍会被内联，例如表单请求体、`readOnly` 和 `writeOnly` 属性，以及部分 `allOf`、`oneOf` 和 `anyOf` 成员。
- 常量保留所有属性，只有在所有位置都是 `strict` 时才是 `strict`。`strict` 不同的位置，或按 operation 覆盖 `exactOptional` 时，其 schema 会被内联。
- 带 `discriminator` 的 `oneOf` 或 `anyOf`，当选项是引用时生成 `v.union`。
- 名为 `Date` 或 `RegExp` 的组件会加上 `Schema` 后缀。两个同名组件会让生成报错并停止。

### 与 Model 对照检查

Model 和 schema 由不同的生成器生成，两者可能在无人察觉时产生偏差。如果项目在另一个配置中生成 TypeScript model，[`override.modelTypeChecks`](/zh/docs/reference/configuration/output#modeltypechecks) 会让 schema 文件断言每个组件 schema 的输出类型与其 model 一致：

```ts title="orval.config.ts"
export default defineConfig({
  api: {
    output: {
      client: 'fetch',
      target: './src/api/endpoints.ts',
      schemas: './src/api/model',
    },
    input: { target: './petstore.yaml' },
  },
  validation: {
    output: {
      client: 'valibot',
      target: './src/validation/schemas.ts',
      override: {
        valibot: { generateReusableSchemas: true },
        modelTypeChecks: { models: './src/api/model' },
      },
    },
    input: { target: './petstore.yaml' },
  },
});
```

`models` 是另一个配置写入 model 的目录，与它的 `output.schemas` 相同。相对路径从当前配置的 workspace 开始，它可能与另一个配置的 workspace 不同；绝对路径按原样使用。schema 文件会导入该目录，并多出一个仅用于类型的代码块，运行时不受影响：

```ts
import type * as Models from '../api/model';

type Assert<T extends true> = T;
type Extends<A, B> = [A] extends [B] ? true : false;
type SchemaModelTypeChecks = {
  Pet: [
    Assert<Extends<v.InferOutput<typeof Pet>, Models.Pet>>,
    Assert<Extends<Models.Pet, v.InferOutput<typeof Pet>>>,
  ];
};
declare const schemaModelTypeChecks: SchemaModelTypeChecks;
```

该类型不会导出，因此重新导出多个此类文件的 barrel 不会因它而冲突。环境声明 `declare const` 会读取该类型，因此 `noUnusedLocals` 不会报错，且不产生任何代码。

当 schema 与其 model 无法双向赋值时，你自己的 `tsc` 会在该组件的断言处报错：`Type 'false' does not satisfy the constraint 'true'`。

- 两个配置必须使用相同的命名选项，例如 `override.components.schemas`，这样 model 才与 schema 同名。
- 双向可赋值无法发现只在一侧声明的可选属性，也无法发现任一侧为 `any` 的类型。必填属性、可空性、`readonly` 数组、枚举、联合类型以及嵌套或递归类型都能被检出。
- 检查会导入 models 的 `index.ts`，并要求它按名称导出每个组件。请在生成 model 的配置中保持 `indexFiles` 开启（默认即开启）。
- 在 schema 中映射类型的选项，例如 `formatType` 或 `useDates`，在 model 中也必须做同样的映射。请在两个配置中都设置 `useBigInt` 和 `useReadonlyArrays`，这样检查会跳过它们所改变的组件。
- 如果 `tsconfig` 中启用了 `exactOptionalPropertyTypes`，model 会把可选属性写为 `a?: T`，因此请在 `override.valibot` 中设置 `exactOptional: true`，否则每个可选属性都会检查失败。当 Orval 读取的 `tsconfig` 启用了该选项而 `exactOptional` 未开启时，生成时会给出警告。
- `modelTypeChecks` 会拒绝 `useBrandedTypes`、`useNullForOptional`、`enumGenerationType: 'enum'` 和 `namingConvention.properties` 并报错，因为它们会让 model 出现 schema 输出无法匹配的形态。schema 输出的字符串字面量不能赋值给 TypeScript `enum`，因此生成 model 的配置中也请使用 `'const'` 或 `'union'`。

#### 被跳过的组件

Orval 有意让某些 schema 的类型比 model 更宽松，因此在这些地方没有任何 schema 能与 model 一致。包含这类写法的组件不会生成断言，代码块中会有一条注释说明原因，文件仍可正常编译：

```ts
type SchemaModelTypeChecks = {
  Pet: [
    Assert<Extends<v.InferOutput<typeof Pet>, Models.Pet>>,
    Assert<Extends<Models.Pet, v.InferOutput<typeof Pet>>>,
  ];
  // Point: skipped, prefixItems is validated as an array of unknown
};
declare const schemaModelTypeChecks: SchemaModelTypeChecks;
```

引用了被跳过组件的组件也会被跳过，因为它的输出类型包含对方的类型。这些写法包括：

- `prefixItems`（元组）按 `unknown` 数组校验。
- 无法保留的循环引用按 `unknown` 校验。
- 二进制字符串（例如 `format: binary`）按 `File` 校验，而 model 将其类型写为 `Blob`。
- 可选属性上的 `default` 只让输出中的键变为必填。对 Valibot 而言，引用了带 `default` 的 schema 的属性也属于这种情况。
- `properties` 旁边的 `additionalProperties` 在 model 中是 `unknown` 类型，而 schema 会校验它。
- 与同一 schema 的 `properties` 并列的 `enum` `allOf` 成员，在 model 中是备选项，而在 schema 中是交叉。
- 没有类型的 schema，例如 `{}` 或只有 `description` 的 schema，按 `unknown` 校验，而 model 将其类型写为 `{}`。
- 没有类型、只描述对象的 schema，即只带 `additionalProperties`、`patternProperties` 或空 `properties` 的 schema，在任意层级（包括属性和 `allOf` 成员）都按 `unknown` 校验，而 model 将其类型写为对象。
- 值为对象或数组的 `const` 不会被校验，带有对象或数组成员的 `enum` 按 `unknown` 校验。
- 没有任何属性声明的必填键，例如只有 `required: [id]` 而没有 `properties`，按 `unknown` 校验，而 model 会省略该键。
- `oneOf` 或 `anyOf` 的 schema 要求某个键，而只有其分支声明了它，例如 `required: [id]` 旁有一个分支把 `id` 写为可选，该键会在每个声明它的分支中变为必填，而 model 保持各分支的原有声明。
- 与对象的属性并列、只要求若干键的 `oneOf` 或 `anyOf` 分支，例如 `{ required: [id] }`，会按带有这些键的对象校验，而 model 将其类型写为 `unknown`。
- 启用 `useBigInt` 时，64 位整数（`format: int64` 或 `uint64`）在 model 中是 `bigint`，在 schema 中是 `number`。
- 启用 `useReadonlyArrays` 时，数组在 model 中是 `readonly`，而 schema 的输出不是。
- 引用数组的 `$ref` 旁边的 `readOnly` 会让输出变为 `readonly`，而 model 不会。
- 数组 `items` 中的 `readOnly` 数组在 schema 中是 `readonly`，而 model 把 `readonly` 写在外层数组上。
- 类型中含 `null` 的 `const`，model 会去掉 `null`。
- 所有属性都是 `const` 的组件，model 会写成常量对象，因此每个键都是必填。带有可选 `const` 属性的组件与 schema 不一致。
- 在同一 schema 的 `properties` 或 `allOf` 旁边，`oneOf` 或 `anyOf` 含有 `null`、可空或 `enum` 的备选项：model 会合并备选项并丢弃枚举旁的自有属性，而 schema 做交叉。

## 用法

### 解析数据

```ts
import * as v from 'valibot';
import { CreatePetsBody } from './src/api/schemas';

const pet = v.parse(CreatePetsBody, { id: 1, name: 'Buddy', tag: 'dog' });
// => { id: 1, name: "Buddy", tag: "dog" }
```

### 类型推断

```ts
import * as v from 'valibot';
import { CreatePetsBody } from './src/api/schemas';

type Pet = v.InferOutput<typeof CreatePetsBody>;

const pet: Pet = { id: 1, name: 'Buddy', tag: 'dog' };
```

### 安全解析

```ts
import * as v from 'valibot';
import { CreatePetsBody } from './src/api/schemas';

const result = v.safeParse(CreatePetsBody, unknownData);

if (result.success) {
  console.log(result.output);
} else {
  console.error(result.issues);
}
```

## 映射规则

- `oneOf` 和 `anyOf` 生成 `v.union`；设置了 `discriminator` 时生成 `v.variant`。`allOf` 生成 `v.intersect`。
- 对象会去掉未知的键。`strict` 选项生成 `v.strictObject`，`additionalProperties` 生成 `v.looseObject` 或 `v.record`。
- `date` 和 `date-time` 字符串按 ISO 日期校验。设置 `override.useDates` 后会转换为 `Date`。
- 二进制字段（`format: binary`）生成 `v.file()`，包括 `multipart/form-data` 请求体中的文件字段。
- 请求体中会去掉 `readOnly` 属性，响应中会去掉 `writeOnly` 属性。带 `items` 的 `readOnly` 数组会加上 `v.readonly()`，因此其输出与模型一样是只读数组。`suppressReadonlyModifier` 会同时关闭两者的只读修饰。
- 与 schema 不符的 `default` 会被去掉，并给出警告。

## 限制

- 循环 `$ref` 在被内联的位置按 `unknown` 校验，并给出警告。设置 `generateReusableSchemas` 后，组件常量通过 `v.lazy` 递归校验。
- `prefixItems` 元组按 `unknown[]` 校验，并给出警告。
- 当 `readOnly` 数组中的某个元素校验失败时，valibot 会跳过该数组自身的检查，例如 `maxItems`。包含该数组（或包含它的对象）的 `v.union` 随后只报告一个通用错误，而不是该元素的具体错误。日期转换或 `formatType` 解码器对校验失败的字符串也有同样的影响。
- 除非设置 [`generateReusableSchemas`](#可复用-schema)，否则每个 `$ref` 都会被内联，共享的 schema 可能让输出变得很大。内联单个 schema 超过 250,000 个 schema 节点时会报错并停止。
- `oneOf` 不检查是否恰好只有一个备选项匹配。
- 在 `allOf` 交叉类型中，`strict` 对象会生成为 `v.object`，多余的键会被去掉而不是报错。与对象成员并列的开放成员（`additionalProperties: true`）会被省略，多余的键同样会被去掉。
- 设置 `schemas: { type: 'valibot' }` 并开启 client 的 `runtimeValidation` 后，生成的 client 用 Valibot 校验响应。支持 `fetch`、`httpClient: 'fetch'` 的 query 类 client 和 `swr`、`angular` 以及 `angular-query`；axios client 不校验响应。详见英文文档。

## 与 HTTP Client 结合使用

`valibot` client 只生成 schema。若要与其他 client 配合，请在单独的输出中生成该 client，然后自行解析响应：

```ts
import * as v from 'valibot';
import { showPetById } from './src/api/endpoints';
import { ShowPetByIdResponse } from './src/api/schemas';

const response = await showPetById('1');
const pet = v.parse(ShowPetByIdResponse, response.data);
```
