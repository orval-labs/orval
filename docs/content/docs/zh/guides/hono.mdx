根据你的 OpenAPI 规范生成带有完整校验能力的 [Hono](https://hono.dev/) 服务端模板。

## 配置

将 `client` 选项设置为 `hono`：

```ts title="orval.config.ts"
import { defineConfig } from 'orval';

export default defineConfig({
  petstore: {
    input: {
      target: './petstore.yaml',
    },
    output: {
      mode: 'split',
      client: 'hono',
      target: 'src/petstore.ts',
      override: {
        hono: {
          handlers: 'src/handlers',
        },
      },
    },
  },
});
```

## 生成的文件

```
src/
├── handlers/
│   ├── createPets.ts
│   ├── listPets.ts
│   ├── showPetById.ts
│   └── updatePets.ts
├── petstore.ts           # 带路由的 Hono app
├── petstore.context.ts   # 类型安全的 context
├── petstore.schemas.ts   # 请求/响应 schema
├── petstore.validator.ts # Hono validator
└── petstore.zod.ts       # Zod schema
```

## Handler（处理器）模板

Orval 会生成内置校验能力的 Handler（处理器）模板：

```ts title="src/handlers/listPets.ts"
/**
 * Generated by orval 🍺
 * Do not edit manually.
 * Swagger Petstore
 * OpenAPI spec version: 1.0.0
 */
import { createFactory } from 'hono/factory';
import { zValidator } from '../petstore.validator';
import { ListPetsContext } from '../petstore.context';
import { ListPetsQueryParams, listPetsResponse } from '../petstore.zod';

const factory = createFactory();

export const listPetsHandlers = factory.createHandlers(
  zValidator('query', ListPetsQueryParams),
  zValidator('response', listPetsResponse),
  async (c: ListPetsContext) => {
    // 在这里实现你的业务逻辑
  },
);
```

## 实现 Handlers（处理器）

把你的业务逻辑添加到生成的 Handlers（处理器）中：

> 重新运行 orval 时，会根据
> [`override.hono.handlerGenerationStrategy`](/docs/reference/configuration/output#handlergenerationstrategy)
>（默认值为 `smart`）来协调 Handler 文件。使用 `smart` 时，orval 只会更新它自己拥有的部分，也就是它自己的 imports（导入项的名称、路径、大小写）和 `zValidator(...)` 参数，并为新增操作追加 Handlers；你的自定义 imports、middleware、中间的 Handler body 以及顶层 helper 都会被保留。使用 `skip` 可以冻结文件，使用 `full` 则会启用旧行为，重建外层包装并只保留 body。

```ts title="src/handlers/listPets.ts"
export const listPetsHandlers = factory.createHandlers(
  zValidator('query', ListPetsQueryParams),
  zValidator('response', listPetsResponse),
  async (c: ListPetsContext) => {
    return c.json([
      { id: 1, name: 'Buddy' },
      { id: 2, name: 'Max' },
    ]);
  },
);
```

## 运行服务

```bash
wrangler dev src/petstore.ts
curl http://localhost:8787/pets
# => [{"id":1,"name":"Buddy"},{"id":2,"name":"Max"}]
```

## 组合路由（tags-split）

对于更大的 API，可以使用带组合路由的 `tags-split` 模式：

```ts title="orval.config.ts"
import { defineConfig } from 'orval';

export default defineConfig({
  petstore: {
    input: {
      target: './petstore.yaml',
    },
    output: {
      mode: 'tags-split',
      client: 'hono',
      target: 'src/endpoints',
      schemas: 'src/schemas',
      override: {
        hono: {
          compositeRoute: 'src/routes.ts',
        },
      },
    },
  },
});
```

这会生成一个组合后的 routes（路由）文件：

```ts title="src/routes.ts"
import { Hono } from 'hono';
import {
  listPetsHandlers,
  createPetsHandlers,
  showPetByIdHandlers,
} from './endpoints/pets/pets.handlers';

const app = new Hono();

app.get('/pets', ...listPetsHandlers);
app.post('/pets', ...createPetsHandlers);
app.get('/pets/:petId', ...showPetByIdHandlers);

export default app;
```
