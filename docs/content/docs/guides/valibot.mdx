description: Generate Valibot schemas from OpenAPI

Generate [Valibot](https://valibot.dev/) schemas from your OpenAPI specification for runtime validation.

## Configuration

Set the `client` option to `valibot`:

```ts title="orval.config.ts"
import { defineConfig } from 'orval';

export default defineConfig({
  petstore: {
    output: {
      client: 'valibot',
      mode: 'single',
      target: './src/api/schemas.ts',
    },
    input: {
      target: './petstore.yaml',
    },
  },
});
```

## Generated Output

Orval generates a Valibot schema for the params, query, headers, body and response of each operation. The body and response schemas come from JSON, `multipart/form-data` or `application/x-www-form-urlencoded` content, and the response schema from the first of `200`, `2XX`/`2xx` and the other 2xx responses (except `204` and `205`) that has such content. Other media types, such as `text/plain`, get no schema:

```ts
import * as v from 'valibot';

export const CreatePetsBody = v.object({
  id: v.pipe(v.number(), v.integer()),
  name: v.string(),
  tag: v.optional(v.string()),
});
```

## Options

Options live under [`override.valibot`](/docs/reference/configuration/output#overridevalibot):

- `strict` - per location (`param`, `query`, `header`, `body`, `response`), emit `v.strictObject` instead of `v.object`. All `false` by default.
- `generate` - per location, choose which schemas are generated. All `true` by default.
- `exactOptional` - use `v.exactOptional` for optional properties, for projects with `exactOptionalPropertyTypes`. `false` by default. Can also be set per operation or tag.
- `generateReusableSchemas` - emit each component schema once and reference it, instead of inlining every `$ref`. `false` by default. See [Reusable Schemas](#reusable-schemas).

## Reusable Schemas

By default every `$ref` is inlined, which makes the output large for a spec with many shared components. With `generateReusableSchemas`, each `#/components/schemas/*` entry becomes one exported constant:

```ts title="orval.config.ts"
export default defineConfig({
  petstore: {
    output: {
      client: 'valibot',
      target: './src/api/schemas.ts',
      override: { valibot: { generateReusableSchemas: true } },
    },
    input: { target: './petstore.yaml' },
  },
});
```

```ts
export type Pet = {
  name: string;
  friends?: Pet[] | undefined;
};

export type PetInput = {
  name: string;
  friends?: PetInput[] | undefined;
};

export const Pet = v.object({
  name: v.string(),
  friends: v.optional(
    v.array(v.lazy((): v.GenericSchema<PetInput, Pet> => Pet)),
  ),
});

export const ListPetsResponse = v.array(Pet);
```

The constants go next to the operations: into the target in `single` mode, into a `*.schemas.ts` file in the other modes. A reference that closes a cycle reads through `v.lazy`.

Each constant on a cycle also gets two exported types: `Pet` for its output and `PetInput` for its input. The `v.lazy` getter uses them, so the recursive field is typed `Pet[]` instead of `unknown`. When another schema already has the name `PetInput`, the input type becomes `PetInput2`. A field converted by an inline `formatType` `decode`, such as `(value) => dayjs(value)`, is typed `unknown` in these types. Name a function, such as `'dayjs'`, to type it with that function's return type.

### Limitations

- It can't be combined with `output.schemas` yet: generation fails with an error.
- A `$ref` is still inlined where a constant would validate differently, such as form bodies, `readOnly` and `writeOnly` properties, and some `allOf`, `oneOf` and `anyOf` members.
- A constant keeps all its properties and is `strict` only when every location is. A location with a different `strict`, or an operation override of `exactOptional`, inlines its schemas.
- A `oneOf` or `anyOf` with a `discriminator` becomes `v.union` when an option is a reference.
- A component named `Date` or `RegExp` gets a `Schema` suffix. Two components with the same name stop generation with an error.

## Usage

### Parsing Data

```ts
import * as v from 'valibot';
import { CreatePetsBody } from './src/api/schemas';

const pet = v.parse(CreatePetsBody, { id: 1, name: 'Buddy', tag: 'dog' });
// => { id: 1, name: "Buddy", tag: "dog" }
```

### Type Inference

```ts
import * as v from 'valibot';
import { CreatePetsBody } from './src/api/schemas';

type Pet = v.InferOutput<typeof CreatePetsBody>;

const pet: Pet = { id: 1, name: 'Buddy', tag: 'dog' };
```

### Safe Parsing

```ts
import * as v from 'valibot';
import { CreatePetsBody } from './src/api/schemas';

const result = v.safeParse(CreatePetsBody, unknownData);

if (result.success) {
  console.log(result.output);
} else {
  console.error(result.issues);
}
```

## Mapping

- `oneOf` and `anyOf` become `v.union`, or `v.variant` when a `discriminator` is set. `allOf` becomes `v.intersect`.
- Objects strip unknown keys. The `strict` option emits `v.strictObject`, and `additionalProperties` emits `v.looseObject` or `v.record`.
- `date` and `date-time` strings are validated as ISO dates. With `override.useDates` they are converted to `Date`.
- Binary fields (`format: binary`) become `v.file()`, including file parts in `multipart/form-data` bodies.
- `readOnly` properties are left out of request bodies, and `writeOnly` properties out of responses. A `readOnly` array with `items` gets `v.readonly()`, so its output is a readonly array, as in the model. `suppressReadonlyModifier` turns this off for both.
- A `default` that does not fit its schema is left out, with a warning.

## Limitations

- A circular `$ref` is validated as `unknown`, with a warning, wherever it is inlined. With `generateReusableSchemas`, component constants validate recursively through `v.lazy`.
- `prefixItems` tuples are validated as `unknown[]`, with a warning.
- When an item of a `readOnly` array fails a check, valibot skips the array's own checks, such as `maxItems`. A `v.union` around the array, or around an object that contains it, then reports one generic issue instead of the item's issue. A date conversion or `formatType` decoder has the same effect on a string that fails a check.
- Every `$ref` is inlined unless [`generateReusableSchemas`](#reusable-schemas) is set, so shared schemas can make the output large. Inlining one schema stops with an error past 250,000 schema nodes.
- `oneOf` does not check that exactly one alternative matches.
- Inside an `allOf` intersection, `strict` objects are emitted as `v.object`, so extra keys are stripped instead of rejected. An open member (`additionalProperties: true`) next to an object member is left out, so extra keys are stripped too.
- Valibot schemas are not wired into the HTTP clients yet: `schemas: { type: 'valibot' }` and runtime validation of responses are not available.

## Combining with HTTP Clients

The `valibot` client generates schemas only. To use it with another client, generate that client in a separate output and parse responses yourself:

```ts
import * as v from 'valibot';
import { showPetById } from './src/api/endpoints';
import { ShowPetByIdResponse } from './src/api/schemas';

const response = await showPetById('1');
const pet = v.parse(ShowPetByIdResponse, response.data);
```
